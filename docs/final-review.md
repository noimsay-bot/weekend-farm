# 마감 점검 보고서 (P10)

작성 기준: 2026-10-01, 커밋 기준 `main`. 자동 검사: `npm test` (단위·DB·RLS 테스트), `npm run lint`, `npm run build`.

## 1. 모바일 레이아웃

- 모든 화면이 최대 폭 448px(`max-w-md`) + 좌우 16px 여백으로 360px 폭에서 가로 스크롤 없이 표시되도록 구성했다.
- 360~390px 에뮬레이션으로 직접 확인한 화면: 로그인, 농장 만들기(지도), 계획 편집기(격자·칠하기·경고 상세), 캘린더, 밭 대시보드(배지·상세 시트).
- 격자 밭은 기본 화면 폭에 맞추고, 확대(+)하면 그 영역만 가로 스크롤된다. 칠하기 모드에서는 드래그가 스크롤 대신 칠하기로 동작(`touch-action: none`), '보기' 모드에서는 스크롤된다.
- 하단 메뉴(밭·캘린더·기록·설정)는 안전 영역(`safe-area-inset-bottom`)을 고려한다.
- 확인 못 한 것: 실제 갤럭시 기기에서의 설치·푸시 수신·위치 권한 흐름 (앱 내 브라우저 제한으로 서비스 워커를 등록할 수 없었음).

## 2. RLS

- `supabase/tests`의 PGlite 테스트가 매 실행마다 확인한다.
  - public 스키마의 **모든 테이블에 RLS가 켜져 있는지** 검사 (새 테이블을 추가해 RLS를 빠뜨리면 테스트가 실패).
  - 비멤버는 다른 농장의 농장·멤버·초대·계획·칸·작물 계획·식재·작업·기록·설정을 읽거나 쓸 수 없음.
  - 작물 계열 테이블은 일반 사용자 읽기 전용, 확정 전(draft) 작물은 관리자만 조회. 쓰기는 `app_admins`만.
  - 푸시 구독·알림 설정은 본인 것만.
  - 날씨 테이블은 읽기 전용 (쓰기는 크론의 service role).
- view(`crop_variety_values`, `active_plan_crops`)는 `security_invoker`로 호출자 권한의 RLS를 따른다.
- security definer 함수는 모두 함수 안에서 `is_farm_member` 또는 `is_app_admin`을 확인한다. 내부용 함수(`finalize_plan`, `release_carried_cells`)는 `authenticated` 실행 권한을 회수했다.
- 계획 상태(draft/pending/confirmed)는 트리거로 직접 변경을 막고 함수로만 바꾼다.
- 사진은 비공개 버킷 `work-photos`, 경로 첫 폴더가 농장 id이며 멤버만 접근. 화면에는 1시간짜리 서명 URL로만 보인다.
- service role 키는 서버(크론)와 로컬 수집 스크립트에서만 쓰고, `NEXT_PUBLIC_`으로 노출하지 않는다.

## 4. 남은 이슈 (사용자 확인·결정 필요)

1. **마이그레이션 적용**: `supabase/migrations`의 P1~P5 파일을 이름 순서대로 SQL Editor에서 실행해야 한다.
2. **작물 확정 방식 (2026-10-01)**: 원문이 있는 작물은 `/admin/crops`에서 한 번에(또는 작물별로) '간단 확정'할 수 있다 — 원문 추출값은 승인, 값이 없는 필드는 빈 값(앱에서 '모름')으로 확정. 다른 작물의 원문은 빌려 쓰지 않는다(봄동과 배추는 시기·재배법이 다름 — 사용자 결정). 콩·고구마·케일·봄동·돌산갓 등 39종은 농사로 텃밭가꾸기에 글이 없어 원문 없음 → 다른 농사로 자료(작목정보·농업기술길잡이) 확보 방법 검토 중.
   **API 키와 수집 실행**: 키 발급 후 `npm run collect` → `missing_report.md` 확인 → `/admin/crops`에서 필드별 승인·입력·확정. 확정된 작물이 없으면 계획 화면에서 칠할 작물이 없다.
3. **농사로 텃밭 원문 형식**: 추출 규칙은 실제 원문 4건(대파·고추·상추·배추)으로 만들고 테스트했다. 다른 작물은 형식이 달라 값 대신 근거 문장만 남는 필드가 많을 수 있다(관리자 화면에서 직접 입력).
4. **API 응답 형식 (키 발급 후 확인, 2026-10-01)**:
   - 텃밭가꾸기: 상세는 `fildMnfctView`, 본문은 `cn`(HTML).
   - 주간농사정보: 본문 없이 첨부(hwpx·hwp·pdf)만 준다. 크론이 hwpx를 받아(`src/lib/hwpx.ts`) 앞쪽 '요약'의 밭작물·채소 항목(`• (작물) 내용`)을 확정 작물과 맞춰 저장한다.
   - 농작물재해예방정보: 목록(`frcDsstrPrevntLst`)에 호별 .hwp 첨부만 있어 수집하지 않는다. 기상특보 알림은 대응 문구 없이 나가며, 문구가 필요하면 `weather_response_guides`에 직접 넣는다.
   - 비료 표준사용량: 작물코드는 분류 2자리+번호 3자리(01~08이 텃밭 작물). 작물명은 '배추(노지재배)'처럼 재배형이 붙어 괄호 앞 이름으로 맞추고 노지 → 평야지 순으로 고른다.
5. **강수량 기준 3개 미정**: 강우 판정 mm, 물주기로 치는 mm, 배수점검 mm는 계획서상 미확정이라 비워 두었다. 비워 두면 각각 "확률만 판정", "비 자동 기록 안 함", "호우특보 때만 경고"로 동작한다. 설정 > 농장 기준값에서 정한다. 입력란에 추천값(강우 1mm, 물주기 10mm, 배수점검 30mm — 기상 기준·텃밭 관행 기반, 농사로 수치 아님)과 흙 종류별 조정 안내를 보여 준다.
6. **앱이 정한 기준 두 가지**: 서리 주의는 예보 최저기온 0℃ 이하, 폭염기 고온은 기상청 폭염주의보 기준인 일 최고 33℃ 이상을 쓴다 (작물 재배 수치가 아닌 기상 기준).
7. **지역 판정**: 북위 36°를 경계로 중부/남부, 제주를 나누는 근사 규칙. 텃밭 원문 달력은 지역 구분이 없어 '전국'으로 저장되므로, 지역별 관행 시기 자료가 들어오기 전까지는 전국 값을 쓴다.
8. **밭만들기 예정일**: 농사로 데이터에 밭만들기 시점 일수가 구조화되어 있지 않아 "파종·정식일까지"로 잡았다 (배지는 그 5일 전부터 표시).
9. **작물 궁합 데이터 없음**: 농사로 '섞어짓기' 글에 작물 쌍별 궁합이 없어 궁합 표시·경고는 데이터가 들어오기 전까지 나타나지 않는다.
10. **실시간 공동 반영**: 밭 대시보드가 Supabase Realtime으로 `tasks`·`work_logs` 변경을 구독해 바로 다시 불러온다 (`20261002000001_realtime.sql` 적용 필요). 적용 전에는 앱으로 돌아올 때만 다시 불러온다.
